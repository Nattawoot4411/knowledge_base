    บทที่ 3: เงื่อนไขและการวนลูป (Conditions and Loops)

    ในการพัฒนาโปรแกรมคอมพิวเตอร์ การควบคุมทิศทางการทำงานของโค้ด (Control Flow) ถือเป็นหัวใจสำคัญที่ทำให้โปรแกรมมีความฉลาดและสามารถตอบสนองต่อสถานการณ์ที่แตกต่างกันได้ โดยปกติแล้วโปรแกรมจะทำงานเรียงลำดับจากบนลงล่างบรรทัดต่อบรรทัด แต่ในความเป็นจริง เรามักต้องการให้โปรแกรม "ตัดสินใจ" ทำงานบางอย่างเมื่อเข้าเงื่อนไขเฉพาะ หรือ "ทำซ้ำ" กระบวนการเดิมเพื่อลดความซ้ำซ้อนในการเขียนโค้ด บทเรียนนี้จะครอบคลุมสถาปัตยกรรมการควบคุมโปรแกรมด้วยคำสั่งเงื่อนไขที่ซับซ้อนขึ้น และการจัดการการวนซ้ำในรูปแบบต่างๆ

    จุดประสงค์การเรียนรู้

    เมื่อศึกษาบทเรียนนี้จบแล้ว ผู้เรียนสามารถ: * เข้าใจหลักการและสามารถเขียนโครงสร้างเงื่อนไขแบบซ้อนทับ (Nested if) ได้อย่างถูกต้อง * ประยุกต์ใช้ตัวดำเนินการทางตรรกศาสตร์เพื่อตรวจสอบหลายเงื่อนไขพร้อมกันได้ * เลือกใช้งานคำสั่ง switch-case สำหรับการแยกกรณีทำงานได้อย่างเหมาะสม * เข้าใจกลไกการทำงานและสามารถประยุกต์ใช้การวนลูปแบบ for และ while ได้ * ควบคุมทิศทางภายในการวนลูปด้วยคำสั่ง break และ continue ได้อย่างถูกต้อง

    1. การควบคุมการทำงานด้วยเงื่อนไขซ้อนทับ (Nested Conditions)

    ในการตรวจสอบเงื่อนไข บางครั้งการตัดสินใจหนึ่งๆ จำเป็นต้องอาศัยปัจจัยหลายอย่างที่ต้องพิจารณาตามลำดับขั้น เราสามารถนำโครงสร้างคำสั่งเงื่อนไขมาซ้อนเข้าไปในบล็อกของคำสั่งเงื่อนไขอื่นได้

    • หลักการสำคัญ: คำสั่ง if ที่อยู่ด้านใน จะถูกประมวลผลก็ต่อเมื่อเงื่อนไขของคำสั่ง if ในระดับที่ครอบมันอยู่ (ชั้นนอกสุด) มีค่าความจริงเป็น true เท่านั้น
    • รายละเอียดเชิงลึก: การซ้อนทับกันไม่จำเป็นต้องอยู่ภายใต้บล็อก if เสมอไป แต่ยังสามารถนำไปซ้อนไว้ในบล็อกของ else if หรือ else ได้ ขึ้นอยู่กับตรรกะของโปรแกรมว่าต้องการให้ประเมินเงื่อนไขย่อยนั้นในจังหวะใด

    [!WARNING] แม้การเขียนเงื่อนไขซ้อนทับจะช่วยให้กรองข้อมูลได้ละเอียด แต่หากมีการซ้อนกันลึกมากเกินไป (Deeply Nested) จะทำให้โค้ดอ่านยาก สับสน และเกิดข้อผิดพลาดในการไล่ตรรกะได้ง่ายขึ้น

    ตัวอย่างประกอบ:

    // การตรวจสอบสิทธิ์การเข้าใช้งานระบบ
let isUserLoggedIn = true;
let userRole = "admin";

if (isUserLoggedIn) {
    // เงื่อนไขชั้นใน จะทำงานเมื่อ Logged In แล้วเท่านั้น
    if (userRole === "admin") {
        console.log("ยินดีต้อนรับ ผู้ดูแลระบบ คุณมีสิทธิ์จัดการระบบเต็มรูปแบบ");
    } else {
        console.log("ยินดีต้อนรับ ผู้ใช้งานทั่วไป");
    }
} else {
    console.log("กรุณาเข้าสู่ระบบก่อนใช้งาน");
}

    2. การประเมินหลายเงื่อนไขร่วมกัน (Compound Conditions)

    เพื่อแก้ปัญหาการใช้ if ซ้อนกันหลายชั้นจนโค้ดซับซ้อน เราสามารถรวบรวมเงื่อนไขทั้งหมดมาประเมินผลพร้อมกันในบรรทัดเดียวได้ โดยอาศัยตัวดำเนินการทางตรรกศาสตร์ (Logical Operators)

    • หลักการสำคัญ: ใช้ตัวดำเนินการ && (AND) และ || (OR) เป็นตัวเชื่อมประโยคเงื่อนไข
      • && (AND): คำสั่งจะทำงานก็ต่อเมื่อเงื่อนไขย่อย ทุกอัน ต้องเป็นจริงทั้งหมด
      • || (OR): คำสั่งจะทำงานเมื่อมีเงื่อนไขย่อย อย่างน้อยหนึ่งอัน เป็นจริง
    • รายละเอียดเชิงลึก: เมื่อมีการเชื่อมเงื่อนไขมากกว่า 2 นิพจน์ ควรใช้วงเล็บ () เพื่อจัดกลุ่มเงื่อนไขให้ชัดเจนว่าต้องการให้โปรแกรมประเมินผลกลุ่มใดก่อน-หลัง ซึ่งจะช่วยป้องกันความผิดพลาดทางตรรกะ (Logic Error) ที่อาจเกิดขึ้นได้

    [!IMPORTANT] วงเล็บมีความสำคัญมากในการลำดับความสำคัญของการดำเนินการ (Precedence) หากไม่ใส่วงเล็บ โปรแกรมอาจตีความลำดับการตรวจสอบผิดไปจากที่ผู้เขียนตั้งใจไว้

    ตัวอย่างประกอบ:

    // ตรวจสอบสิทธิ์การรับทุนการศึกษา (ต้องเกรดถึงเกณฑ์ และ รายได้น้อย หรือ เป็นนักกีฬา)
let gpa = 3.8;
let lowIncome = false;
let isAthlete = true;

if (gpa >= 3.5 && (lowIncome === true || isAthlete === true)) {
    console.log("คุณมีคุณสมบัติผ่านเกณฑ์การพิจารณารับทุน");
}

    3. การเลือกกรณีการทำงานด้วย Switch - Case

    เมื่อตัวแปรหนึ่งตัวมีโอกาสที่จะมีค่าที่เจาะจงได้หลายรูปแบบ และแต่ละรูปแบบต้องการให้โปรแกรมทำงานแตกต่างกัน การใช้ if-else if ต่อกันยาวๆ อาจทำให้โค้ดไม่สวยงามและอ่านยาก คำสั่ง switch-case จึงถูกออกแบบมาเพื่อจัดการกับปัญหานี้

    • หลักการสำคัญ: switch-case นำค่าของตัวแปรหรือนิพจน์ตั้งต้น มาตรวจสอบเทียบกับค่าในแต่ละ case หากตรงกับ case ใด ก็จะเข้าไปทำงานในบล็อกคำสั่งของ case นั้น
    • รายละเอียดเชิงลึก:
      • break: เป็นคีย์เวิร์ดบังคับที่ควรใส่ไว้ท้ายสุดของแต่ละ case เพื่อสั่งให้โปรแกรม "หยุด" และกระโดดออกจากโครงสร้าง switch ทันที หากไม่มี break โปรแกรมจะทำงานทะลุลงไปยังคำสั่งใน case ถัดไปเรื่อยๆ โดยไม่สนใจว่าเงื่อนไขจะตรงหรือไม่ (เรียกว่าพฤติกรรม Fall-through) ซึ่งอาจส่งผลให้ผลลัพธ์การทำงานผิดเพี้ยนไป
      • การรวบกลุ่มเงื่อนไข: หากมีหลายๆ case ที่ต้องการให้ผลลัพธ์การทำงานออกมาเหมือนกัน เราสามารถเขียน case เหล่านั้นติดกันได้โดยไม่ต้องมีคำสั่งคั่น แล้วไปเขียนคำสั่งและ break ที่ case สุดท้ายของกลุ่ม
      • default: ทำหน้าที่คล้าย else ในคำสั่ง if คือเป็นกรณีครอบจักรวาล จะทำงานก็ต่อเมื่อค่าที่ตรวจสอบไม่ตรงกับ case ใดๆ เลยที่กำหนดไว้ก่อนหน้า (จะมีหรือไม่มีก็ได้)

    [!NOTE] switch-case เหมาะกับการเปรียบเทียบค่าที่ตายตัวและแน่นอน (Exact Match) ไม่สามารถใช้กับการประเมินช่วงค่าข้อมูล (เช่น มากกว่า, น้อยกว่า) ได้โดยตรงเหมือนคำสั่ง if

    ตัวอย่างประกอบ:

    let packageType = "Gold";

switch (packageType) {
    case "Silver":
        console.log("สิทธิ์การเข้าถึงระดับพื้นฐาน");
        break;
    case "Gold":
    case "Platinum": // รวบกลุ่ม Gold และ Platinum ให้แสดงผลลัพธ์เดียวกัน
        console.log("สิทธิ์การเข้าถึงระดับพรีเมียม");
        break;
    default:
        console.log("ไม่พบประเภทแพ็กเกจในระบบ");
        // default โดยปกติอยู่ล่างสุด จึงไม่จำเป็นต้องใส่ break ก็ได้
}

    4. โครงสร้างการทำซ้ำพื้นฐานด้วย For Loop

    หากเราทราบจำนวนครั้งที่แน่นอนในการทำงานซ้ำ การใช้ for loop ถือเป็นโครงสร้างที่เหมาะสมและเป็นระเบียบที่สุด

    • หลักการสำคัญ: คำสั่ง for จะรวบรวมองค์ประกอบสำคัญ 3 ส่วนของการทำซ้ำมาไว้ในวงเล็บเดียวกัน โดยคั่นด้วยเครื่องหมายอัฒภาค (Semicolon ;) ได้แก่:
      1. ค่าเริ่มต้น (Initialization): การประกาศและกำหนดค่าตัวแปรเพื่อใช้เป็นตัวนับรอบ (ทำงานเพียงครั้งเดียวตอนเริ่ม)
      2. เงื่อนไขการทำงาน (Condition): นิพจน์ตรรกศาสตร์ที่จะถูกตรวจสอบก่อนเริ่มรอบใหม่เสมอ หากเป็นจริงจะทำซ้ำ หากเป็นเท็จจะจบการทำงานของลูป
      3. การเปลี่ยนแปลงค่า (Increment/Decrement): การปรับปรุงค่าตัวแปรตัวนับ (เช่น เพิ่มขึ้นทีละ 1, ลดลง, หรือคูณค่า) ซึ่งจะทำงานเมื่อจบคำสั่งในรอบนั้นๆ
    • รายละเอียดเชิงลึก: ตัวแปรนับรอบไม่ได้จำกัดว่าจะต้องเพิ่มค่าทีละ 1 เสมอไป เราสามารถกำหนดให้เพิ่มขึ้นทีละทศนิยม หรือลดค่าลงแบบนับถอยหลังก็ได้

    [!IMPORTANT] โค้ดในส่วนของ "ค่าเริ่มต้น" "เงื่อนไข" และ "การเปลี่ยนแปลงค่า" ต้องสอดคล้องกัน หากกำหนดผิดพลาดอาจทำให้เกิดลูปที่ไม่รู้จบ (Infinite Loop) ได้

    ตัวอย่างประกอบ:

    // แสดงผลแม่สูตรคูณแม่ 5 จำนวน 5 รอบ
for (let counter = 1; counter <= 5; counter++) {
    let result = 5 * counter;
    console.log("5 x " + counter + " = " + result);
}
// ผลลัพธ์: 
// 5 x 1 = 5
// 5 x 2 = 10
// 5 x 3 = 15
// 5 x 4 = 20
// 5 x 5 = 25

    5. การทำซ้ำแบบซ้อนทับ (Nested Loops)

    ในทำนองเดียวกับคำสั่ง if เราสามารถนำลูปไปใส่ไว้ภายในบล็อกการทำงานของลูปอีกตัวหนึ่งได้ เรียกว่าการทำลูปซ้อนลูป

    • หลักการสำคัญ: ลูปที่อยู่ชั้นใน (Inner Loop) จะต้องทำงานตั้งแต่ต้นจนจบกระบวนการครบทุกรอบของมัน สำหรับ "ทุกๆ หนึ่งรอบ" ของลูปชั้นนอก (Outer Loop) เสมอ
    • รายละเอียดเชิงลึก: หากลูปนอกถูกตั้งให้รัน M รอบ และลูปในถูกตั้งให้รัน N รอบ จำนวนครั้งที่คำสั่งภายในลูปชั้นในสุดจะถูกประมวลผลคือ M คูณ N ครั้ง

    [!WARNING] ควรระมัดระวังในการใช้งานลูปซ้อนทับหลายชั้น เพราะจะทำให้โปรแกรมใช้ทรัพยากรการคำนวณสูงและทำงานช้าลงอย่างมากตามจำนวนชั้นที่เพิ่มขึ้น (Time Complexity จะเติบโตแบบทวีคูณ)

    ตัวอย่างประกอบ:

    // การจำลองการสร้างพิกัดตาราง 3x2
for (let row = 1; row <= 3; row++) {      // ลูปชั้นนอก (แถว)
    for (let col = 1; col <= 2; col++) {  // ลูปชั้นใน (คอลัมน์)
        console.log("พิกัด: แถว " + row + ", คอลัมน์ " + col);
    }
}

    6. การควบคุมทิศทางในลูปด้วย Break และ Continue

    ปกติแล้วลูปจะทำงานจนกว่าเงื่อนไขหลักจะเป็นเท็จ แต่เราสามารถแทรกแซงพฤติกรรมนี้ได้จากภายในบล็อกคำสั่งของลูปเอง

    • หลักการสำคัญ:
      • break: เป็นคำสั่งที่ใช้สำหรับ "ทำลาย" หรือ "กระโดดออก" จากลูปนั้นทันที โดยไม่สนใจว่าเงื่อนไขหลักของลูปจะยังคงเป็นจริงอยู่หรือไม่ และข้ามการทำงานที่เหลือในลูปทั้งหมด
      • continue: เป็นคำสั่งสำหรับ "ข้าม" การทำงานใน "รอบปัจจุบัน" ทันที โดยโปรแกรมจะข้ามคำสั่งที่อยู่ใต้ continue ทั้งหมดในรอบนั้น แล้ววกกลับไปตรวจสอบเงื่อนไขหลัก (หรือประมวลผลการเปลี่ยนแปลงค่า) เพื่อเริ่มต้นรอบถัดไปทันที
    • รายละเอียดเชิงลึก: ในกรณีที่มีการวนลูปแบบซ้อนทับ (Nested loops) การทำงานของคำสั่ง break จะมีผลทำให้หลุดออกจากวงลูปชั้นที่คำสั่งนั้นอาศัยอยู่เท่านั้น จะไม่ได้กระโดดออกจากลูปชั้นนอกสุดไปด้วย

    [!NOTE] คำสั่งทั้งสองนี้มักใช้ร่วมกับคำสั่ง if ภายในลูป เพื่อดักจับเงื่อนไขพิเศษบางอย่างในระหว่างการรัน

    ตัวอย่างประกอบ:

    // ตัวอย่างการใช้ break และ continue ร่วมกัน
for (let number = 1; number <= 10; number++) {
    if (number === 4) {
        continue; // ข้ามรอบที่ number มีค่าเท่ากับ 4 (จะไม่ถูกพิมพ์ออกมา)
    }
    if (number === 8) {
        break;    // ยุติการทำงานของลูปทั้งหมดเมื่อ number มีค่าเท่ากับ 8
    }
    console.log("ตัวเลขที่ดำเนินการ: " + number);
}
// ผลลัพธ์: พิมพ์ 1, 2, 3, 5, 6, 7 แล้วหยุดทำงานทันที

    7. การทำซ้ำแบบตรวจสอบเงื่อนไขด้วย While Loop

    ลูปประเภท while จะถูกนำมาใช้ในสถานการณ์ที่เรา ไม่ทราบจำนวนรอบที่แน่นอนล่วงหน้า ว่าโปรแกรมจะต้องวนซ้ำกี่ครั้ง แต่ทราบเพียงว่าโปรแกรมจะหยุดทำงานเมื่อใด (เงื่อนไขใด)

    • หลักการสำคัญ: โครงสร้างจะมีเพียงการตรวจสอบเงื่อนไขก่อนเริ่มทำงาน หากเงื่อนไขในวงเล็บมีค่าความจริงเป็น true จะประมวลผลคำสั่งในบล็อก และจะวนกลับมาเช็คเงื่อนไขซ้ำไปเรื่อยๆ จนกว่าเงื่อนไขจะประเมินผลเป็น false จึงจะหลุดจากลูป
    • รายละเอียดเชิงลึก: ผู้เขียนโปรแกรมจะต้องมีกลไก หรือเขียนคำสั่งบางอย่าง "ภายในบล็อกการทำงาน" ของลูป เพื่อเปลี่ยนแปลงค่าที่เป็นส่วนประกอบของเงื่อนไขหลักให้กลายเป็น false ในท้ายที่สุด

    [!CAUTION] หากในบล็อกคำสั่งของ while ไม่มีคำสั่งใดที่ส่งผลให้เงื่อนไขหลักเปลี่ยนเป็น false ได้เลย (เช่น ระบุเป็น while(true)) โปรแกรมจะติดอยู่ในสภาวะ วงวนไม่รู้จบ (Infinite Loop) ซึ่งจะทำให้ทรัพยากรระบบทำงานหนักจนโปรแกรมค้าง การจะหลุดจาก Infinite Loop ได้ ต้องอาศัยคำสั่ง break ช่วยดักจับภายในเท่านั้น

    ตัวอย่างประกอบ:

    // โปรแกรมสุ่มหาตัวเลขเป้าหมาย
let targetNumber = 7;
let currentGuess = 0;
let attempts = 0;

// ลูปจะทำงานไปเรื่อยๆ ตราบใดที่ยังสุ่มไม่ได้เลข 7
while (currentGuess !== targetNumber) {
    // สมมติสถานการณ์จำลองการเปลี่ยนค่าในแต่ละรอบ
    currentGuess += 1; // ในความเป็นจริงอาจเป็นการรับค่าจากผู้ใช้ หรือการสุ่ม
    attempts++;
}
console.log("พบตัวเลขเป้าหมายในความพยายามครั้งที่: " + attempts);

    สรุปบทเรียน

    การสร้างโปรแกรมที่มีความยืดหยุ่น จำเป็นต้องอาศัยคำสั่งเงื่อนไข (if, switch-case) เพื่อสร้างทางเลือกในการประมวลผลข้อมูล และอาศัยการวนลูป (for, while) เพื่อจัดการกับข้อมูลจำนวนมากหรือกระบวนการที่ซ้ำซ้อนได้อย่างทรงประสิทธิภาพ การเลือกใช้เครื่องมือเหล่านี้ ไม่ว่าจะเป็นการเชื่อมเงื่อนไขด้วยตัวดำเนินการตรรกศาสตร์ การปรับจังหวะการวนซ้ำด้วย break และ continue ขึ้นอยู่กับโครงสร้างตรรกะของโจทย์ปัญหาเป็นสำคัญ ผู้พัฒนาที่ดีควรเลือกใช้โครงสร้างที่ทำให้โปรแกรมทำงานได้ถูกต้อง และโค้ดมีความเป็นระเบียบอ่านง่าย

    ❓ คำถามทบทวน (Review Questions)

    คลิกที่การ์ดคำถามด้านล่างเพื่อแสดงเฉลยคำตอบของคำถามแต่ละข้อ:

    1. การใช้เงื่อนไขซ้อนทับ (Nested if) มีข้อควรระวังใดที่ส่งผลกระทบต่อคุณภาพของโค้ดโปรแกรม?

      ดูเฉลยคำตอบ
      หากมีการซ้อนกันของเงื่อนไขที่ลึกมากเกินไป (Deeply Nested) จะส่งผลให้โค้ดอ่านยากขึ้น เกิดความสับสนในการตรวจสอบตรรกะ และเพิ่มโอกาสการเกิดข้อผิดพลาด (Logic Error) ได้ง่ายขึ้น (หรือเรียกว่า "Pyramid of Doom") แนะนำให้รวบเงื่อนไขด้วยตัวดำเนินการตรรกศาสตร์ หรือขยับย้ายโครงสร้างบางส่วนไปเขียนเป็นฟังก์ชันย่อย

    2. หากต้องการให้คำสั่งประมวลผลเมื่อเงื่อนไขใดเงื่อนไขหนึ่งจากทั้งหมด 3 เงื่อนไขเป็นจริง ควรใช้ตัวดำเนินการทางตรรกศาสตร์ใด?

      ดูเฉลยคำตอบ
      ควรใช้ตัวดำเนินการ || (OR) เพื่อเชื่อมต่อเงื่อนไข เนื่องจากตัวดำเนินการนี้จะให้ผลลัพธ์เป็น true ขอเพียงแค่มีเงื่อนไขย่อยอย่างน้อยหนึ่งตัวเป็นจริง

    3. วงเล็บ () มีความสำคัญอย่างไรเมื่อเราเขียนเงื่อนไขทางตรรกศาสตร์ที่มีความยาวและซับซ้อน?

      ดูเฉลยคำตอบ
      วงเล็บช่วยในการจัดกลุ่มเงื่อนไขและควบคุมลำดับความสำคัญ (Precedence) ของตัวดำเนินการ เพื่อให้โปรแกรมประมวลผลตรงกับลอจิกการทำงานจริงที่เราออกแบบไว้ ช่วยป้องกันข้อผิดพลาดทางตรรกะที่ระบบอาจประเมินผลผิดลำดับ

    4. ในคำสั่ง switch-case หากละเว้นการใส่คีย์เวิร์ด break ในแต่ละกรณี จะเกิดผลลัพธ์การทำงานอย่างไร?

      ดูเฉลยคำตอบ
      จะทำให้เกิดลักษณะการทำงานที่เรียกว่า Fall-through โดยโปรแกรมจะประมวลผลคำสั่งใน case ถัดๆ ไปด้านล่างต่อเนื่องทันทีโดยไม่ต้องตรวจสอบเงื่อนไขความสอดคล้องใดๆ อีก จนกว่าจะไปพบสัญลักษณ์คีย์เวิร์ด break ตัวถัดไป หรือทำงานเสร็จสิ้นกระบวนการทั้งหมดของสวิตช์นั้น

    5. คีย์เวิร์ด default ในโครงสร้าง switch-case เทียบเท่ากับคำสั่งใดในโครงสร้าง if-else?

      ดูเฉลยคำตอบ
      เทียบเท่ากับคำสั่ง else ในโครงสร้าง if-else ซึ่งเป็นตัวคอยดักจับกรณีสุดท้าย (fallback) เมื่อค่าที่นำมาเปรียบเทียบไม่ตรงกับเคสก่อนหน้านี้เลยทั้งหมด

    6. องค์ประกอบ 3 ส่วนที่อยู่ภายในวงเล็บของคำสั่ง for ประกอบด้วยอะไรบ้าง?

      ดูเฉลยคำตอบ
      ประกอบด้วย 3 ส่วนสำคัญ คั่นด้วยเครื่องหมายเซมิโคลอน (;) คือ:
      1. ค่าเริ่มต้น (Initialization): การกำหนดค่าเริ่มต้นตัวแปรนับรอบ (รันครั้งแรกเพียงครั้งเดียว)
      2. เงื่อนไขการทำงาน (Condition): การตรวจสอบค่าความจริงหากสอดคล้องถึงจะรันต่อ
      3. การเปลี่ยนแปลงค่า (Increment/Decrement): การปรับเพิ่มหรือลดตัวแปรตัวนับหลังจากครบรอบคำสั่งภายในลูป

    7. หากมีการเขียนลูปซ้อนลูป (Nested loops) ลูปชั้นในสุดจะทำงานจบกระบวนการกี่ครั้ง หากลูปนอกรัน 5 รอบ และลูปในรัน 3 รอบ?

      ดูเฉลยคำตอบ
      จะรันจบกระบวนการทั้งหมดเป็นจำนวน 15 ครั้ง (มาจากความสัมพันธ์การคูณ 5 x 3 โดยลูปชั้นในสุดจะหมุนรอบตัวเองครบ 3 ครั้ง ทุกครั้งที่ลูปชั้นนอกขยับหมุน 1 รอบ)

    8. ความแตกต่างระหว่างคำสั่ง break และ continue คืออะไร?

      ดูเฉลยคำตอบ
      • break: จะขัดจังหวะการทำงานและทำการกระโดดออกจากลูปปัจจุบันที่อาศัยอยู่นั้นทันที
      • continue: จะข้ามการประมวลผลในส่วนที่เหลือของรอบปัจจุบัน แล้วกระโดดข้ามไปรอเข้าสู่ขั้นตอนการตรวจประเมินเงื่อนไขเพื่อขึ้นรอบการทำงานใหม่

    9. ในการเขียน while loop ปัญหา "วงวนไม่รู้จบ" (Infinite Loop) เกิดขึ้นจากสาเหตุใดเป็นหลัก?

      ดูเฉลยคำตอบ
      เกิดขึ้นเพราะประโยคเงื่อนไขที่กำหนดไว้สำหรับเข้าทำงานวนซ้ำมีค่าสถานะเป็น true ตลอดเวลา โดยไม่มีการสั่งให้ตัวแปรที่เป็นนิพจน์ควบคุมถูกแก้ไขค่าให้กลายเป็น false หรือไม่มีคำสั่ง break เข้ามาทำลายลูปจากภายในบล็อก

    10. สถานการณ์ใดที่การเลือกใช้ while loop จะเหมาะสมกว่าการใช้ for loop?

      ดูเฉลยคำตอบ
      เหมาะกับกรณีที่ "ไม่ทราบล่วงหน้าว่าต้องวนซ้ำกี่รอบจึงจะบรรลุเป้าหมาย" แต่ทราบแน่นอนว่าโปรแกรมควรหยุดหรือดำเนินต่อด้วยเงื่อนไขสภาวะแบบใด เช่น การวนสุ่มรหัสผ่านจนกว่าจะถูกต้อง หรือการคอยรับข้อความป้อนเข้าจนกว่าผู้ใช้งานจะกดปิดระบบ
